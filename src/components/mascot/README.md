# Mascot

A single character in nine states, rendered into one canonical canvas.

## Canonical canvas — supersedes the tight-viewBox-per-state brief

**The original extraction brief required a tight `viewBox` per state. That
requirement is overridden and must not be reintroduced, in whole or in part.**

That requirement is what produced the rescale bug. Each state's crop was sized
to its own content, so the nine states had nine different box sizes and the
character visibly resized on every state change — anywhere between roughly 53px
and 80px of rendered height.

All nine states now render into **one shared canvas, 21.3 x 15.2 units**,
positioned by a per-axis translation derived at build time from the artwork
itself. Nothing per-state is allowed to declare its own canvas.

### Per-axis anchoring

The horizontal and vertical axes anchor to different features, because the
artwork's relationship between body and floor is not consistent across cells.

| axis | anchored to | canonical value |
|---|---|---|
| X | visor centre | 10.5 |
| Y | floor line (ground ellipse `cy`) | 13.3 |

Anchoring X on the floor bar instead would swing the *face* across ~10% of the
canvas width. Anchoring on the visor collapses that spread to 0.25 units,
because the artwork does not drift the face. The floor bar then drifts
horizontally by 10.33–12.30 instead — error spent on the soft glow at the feet,
which is the right place to spend it.

### Canvas width is 21.3, not 21

`needsYou` carries a notification-bell badge whose right edge reaches 21.265
once that state's visor is anchored at 10.5. The original 21-unit width assumed
`needsYou` had no fx at all; it does. Consistent with the rule above, the canvas
grew rather than clipping the badge.

## Anchors are derived, not typed

`src/components/mascot/anchors.ts` is generated by
`npm run extract:anchors`, which reads each state component's artwork and
derives its visor centre and floor-line position. Hand-entered numbers drift the
moment the artwork is re-exported, and a drifted anchor reads as a subtle art
problem rather than a build problem. `test/anchors.test.ts` re-derives from
source and fails if the committed data drifts.

## Addressing parts

Semantic groups carry `data-part` attributes — `glow`, `body`, `eyes`, `fx` —
resolved by a scoped query against the component's own root. Global `id`
selectors are not used for parts, so any number of mascots can coexist in one
document without one instance's lookup resolving to another's.

```tsx
const root = svgRef.current!;
const body = root.querySelector('[data-part="body"]');
```

Gradient and paint-server ids are per-instance, derived from React's `useId()`
with non-alphanumeric characters stripped — React emits ids containing colons
and guillemets, which are awkward inside `url(#...)` references.

## Accepted residual

Body geometry varies between states independently of position — roughly a 12%
spread in width and a 29% spread in height, with `focused` genuinely drawn
shorter. No anchor removes this. Anchoring the vertical axis to the floor line
leaves it reading as squash-and-stretch against a planted floor, which is
accepted for v0.1. Pixel-identical body geometry across all states is a
source-artwork correction, not something the component layer can solve.
